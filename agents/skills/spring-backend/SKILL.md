# spring-backend

The rules live in the hub docs; this skill is the checklist that ties them together. When this skill and a doc disagree, the doc wins: report the mismatch to the Tech Lead.

Sources: `docs/architecture.md` (section 3), `docs/conventions.md` (sections 1–5), `docs/events.md`, `docs/engineering-guidelines.md` (sections 4–5), ADRs 0004, 0005, 0007, 0013–0016, 0018, 0019.

## Stack

Java 25, Spring Boot 4.1 (gateway: 4.0 + Spring Cloud 2025.1), Maven wrapper (`./mvnw`), PostgreSQL + Flyway, Kafka, Redis, OpenTelemetry. Services are **Spring MVC on virtual threads** (`spring.threads.virtual.enabled=true`). Only the gateway is reactive.

## Writing a feature

- **Where:** one package per feature under `io.github.jaouadioussama.pixora.<service>`; controller, service, repository, entity, DTOs, mapper and event payloads are classes in it. Cross-cutting code lives in `config/` and `outbox/`.
- **Visibility:** package-private by default; `public` only when another package needs it.
- **Every package** has `package-info.java` with `@NullMarked`; nullable values are `@Nullable` (JSpecify). NullAway fails the build otherwise.
- **Records** for request/response DTOs, event payloads, `@ConfigurationProperties` and value objects. **No Lombok.** **MapStruct** for entity ↔ DTO.
- **Constructor injection** with `final` fields; never `@Autowired` on fields.
- **Validation:** Bean Validation on request records, `@Valid` in the controller. Business rule violations throw a domain exception that the global handler turns into the right problem response.
- **Errors:** RFC 9457 `ProblemDetail` from the one global handler in `config/`, with `code` (UPPER_SNAKE), `errors` for field errors, `traceId`. A new specific error gets an entry in the hub's `contracts/problem-types.md` (via the contract PR).
- **IDs** are UUIDv7 generated by the service; times are `Instant` in UTC.
- **API shape:** follow the merged OpenAPI contract exactly: `/v1/...` paths inside the service, status codes from conventions 4.4, cursor pagination (`limit`, `cursor` → `{items, nextCursor}`, Spring Data keyset scrolling), `ETag`/`If-Match` with `@Version` on editable resources, `Idempotency-Key` where the contract requires it.
- **Security:** every service is an OAuth2 resource server validating the JWT the gateway relays. Authorization is checked in the service against the resource (is the caller the owner?), never only in the gateway or the UI.
- **Events:** never call `KafkaTemplate` from a feature. Write the change and the outbox row in the **same transaction** through the `outbox` package. Event payloads are records in the feature package, matching the AsyncAPI schema; `eventId` is UUIDv7, key = aggregate id.
- **Consuming events:** idempotent (record `eventId` in `processed_event` in the same transaction as the change), retries with backoff, then `<topic>.DLT`. Never assume order across keys.
- **Calling another service:** only when the plan says so, through a client with Resilience4j (timeout, retry, circuit breaker), forwarding the user's JWT, with a fallback for when it is down.
- **Configuration:** from environment variables through `@ConfigurationProperties` records; nothing environment-specific in code, `application.yml` defaults are for local dev only.
- **Logging:** SLF4J with parameters; no tokens, passwords, emails or full request bodies in logs.

## The gateway (pixora-gateway) is different

- Reactive (Spring Cloud Gateway Server WebFlux, ADR-0018): `SecurityWebFilterChain`, `Mono`/`Flux`, **never `block()`** or any blocking call; tests use `WebTestClient`.
- Mostly configuration: routes (the routing map in conventions 4.2), `oauth2Login`, `TokenRelay`, Spring Session on Redis, CSRF cookie for Angular, `RequestRateLimiter` with `RedisRateLimiter`.
- `/api/**` never redirects to login: it answers `401`.

## Testing

| Layer        | How                                                                                                   | Name    |
| ------------ | ----------------------------------------------------------------------------------------------------- | ------- |
| Unit         | Plain JUnit + AssertJ + Mockito, no Spring                                                            | `*Test` |
| Web slice    | `@WebMvcTest` + MockMvc (gateway: `WebTestClient`)                                                    | `*Test` |
| JPA slice    | `@DataJpaTest` with Testcontainers PostgreSQL                                                         | `*Test` |
| Integration  | `@SpringBootTest` + Testcontainers + `@ServiceConnection`, singleton containers, Awaitility for async | `*IT`   |
| Contract     | Responses / events validated against the hub's OpenAPI / AsyncAPI                                     | `*IT`   |
| Architecture | ArchUnit rules from conventions section 2                                                             | `*Test` |

- Test names: `shouldDoXWhenY()`, body in given / when / then blocks.
- Real engines only (never H2). Each test creates its own data.
- New code coverage ≥ 80% (Sonar gate), but write tests for behaviour, not for the number.

## Commands

- Format: `./mvnw spotless:apply` (CI runs `spotless:check`).
- Fast loop: `./mvnw test`. Everything CI runs: `./mvnw verify`.
- The repo's `CLAUDE.md` lists any extra command.

## Review focus

Ownership checks on every endpoint; transaction boundaries (outbox in the same transaction); N+1 queries and missing indexes (ask the DBA); idempotency of consumers and of `POST`; error responses never leak internals; entities never leave their feature.
